The final check runs inside one database transaction, so two people can never take the same time, even when they click at once.

## The problem

Availability is checked when a guest opens your page and picks a time. Two guests can pick the same slot in the same second. A check-then-book gap is all a double booking needs.

## How it works

The final check does not happen in the page. It runs inside a database transaction guarded by a unique index. A given start time can be held exactly once. If two guests race for it, the database admits one booking and rejects the other.

## A worked example

1. Asha and Dev both open your page and both see 10:30 on Monday.
2. Both confirm within the same second.
3. The database writes Asha's booking. The unique index rejects Dev's.
4. Dev sees a friendly "just taken" message and picks another slot.

## What it does not do

It does not stop you from adding an event straight into Google Calendar. slotLane checks Google Calendar for conflicts before offering times.

See also [Google Calendar](/docs/guides/google-calendar) and [Limits](/docs/limits).
